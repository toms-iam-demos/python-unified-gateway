# Local development runbook

Run the gateway from `gateway.app:app` on loopback port 8001, with SQLite state in
`data/gateway.db`. This release is tested with Python 3.12.12; `.python-version`
records that local interpreter selection. Colima and Docker CLI remain supported;
Docker Desktop is not required.

## Set up

From the repository root, using an installed Python 3.12 interpreter:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-test.txt
mkdir -p data
```

There is no packaging-based editable install or `.env.example` in this checkout.
For live integration work, provision a private `.env` using the actual variables in
[the HMAC runbook](12_connect_hmac.md) and the gateway's existing docusign configuration.
Do not copy production credentials into a test environment.

## Run locally

```sh
GATEWAY_DB_ENABLED=1 GATEWAY_DB_PATH="$PWD/data/gateway.db" \
  .venv/bin/uvicorn gateway.app:app --reload --host 127.0.0.1 --port 8001
```

To load an intentionally configured private `.env`, add `--env-file .env`. Enable
`GATEWAY_EXPLORER_ENABLED=1` only on loopback or behind the established operator policy;
see [explorer setup](13_architecture_explorer.md). The monitor is at
`http://127.0.0.1:8001/webhooks/monitor/ui`.

## Verify

```sh
curl -fsS http://127.0.0.1:8001/health
curl -fsS http://127.0.0.1:8001/health/ready
.venv/bin/python -m unittest discover -s tests -v
```

Inspect response fields: health is a process check; readiness reports schema availability
and can return HTTP 200 with `ready=false`. Neither proves successful webhook persistence
or the HMAC configuration. The tests use synthetic signed requests and temporary SQLite;
no real provider request is made. Unsigned requests to `/webhooks/docusign` are rejected,
and the old example `/webhooks/example` route does not exist.

Raw events are persisted in SQLite. File-based normalized events, projections and replay
folders are architectural concepts, not outputs generated by this current gateway.

## Documentation

```sh
.venv/bin/python -m pip install -r requirements-docs.txt
.venv/bin/python -m mkdocs build --strict
.venv/bin/python -m mkdocs serve
```

Use `mkdocs.yml` for publication. It excludes local genesis/checkpoint material.
The production image uses a separate, restricted build context; see
[release scope](14_release_scope.md) and [Hetzner deployment](11_hetzner_api_ingress.md).
